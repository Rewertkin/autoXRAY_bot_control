# autoXRAY bot control

Telegram-бот для управления клиентами моста [autoXRAY](https://github.com/xVRVx/autoXRAY) (RU -> EU, `bridgeTLSxhttp.sh`) без веб-панели.

## Что умеет

- **Клиенты кнопками**: постоянные или гостевые на 1 день, 7 дней, 30 дней или 4 недели. Гостевой доступ истекает и удаляется автоматически, бот присылает уведомление.
- **Выбор подключений** при создании: `XHTTP TLS stream-up` и/или `RAW VISION` (оба идут через мост RU -> EU).
- **Статус клиента**: онлайн или офлайн, текущие IP с городом, страной и провайдером (геолокация с ротацией ip-api.com, ipwho.is, ipinfo.io, ipapi.co и кэшем), история последних подключений.
- **QR-код и ссылка `vless://`** по кнопке для каждого выданного подключения.
- **Трафик**: сегодня, текущий 30-дневный период и всего. Лимит на 30 дней от даты создания: при 80% и 100% бот предупреждает тебя, доступ не отключается.
- **Проверка моста** (🌉): DNS, TLS-рукопожатие и сертификат зарубежного сервера, открывается ли на нём сайт-заглушка, и проходит ли трафик через всю цепочку RU -> EU.
- **Диагностика сервера** сводкой: службы, Xray API, совпадение клиентов с конфигом, цепочка RU -> NL, DNS, сертификат, порты, время без разрывов связи RU -> NL, аптайм. Цепочку бот проверяет в фоне раз в минуту: разрыв засчитывается, если не прошла и повторная попытка через 5 секунд.
- **Автодиагностика** (включается кнопкой под отчётом диагностики): та же проверка раз в 15 минут в фоне. Бот пишет, когда появились или изменились проблемы, и когда всё снова в порядке.
- **Самоконтроль**: если конфиг Xray перезаписали (например, повторно запустили скрипт моста), бот пришлёт предупреждение с кнопкой восстановления.

Без перезапуска Xray: клиенты добавляются и удаляются через Xray API, остальные подключения не рвутся.

## Как это устроено

```
Telegram <-SOCKS бота -> proxy-0 (EU)- бот (Python, systemd) -xray api-> Xray моста (RU)
                                        |
                                        +- SQLite: клиенты, трафик по часам, сессии, кэш гео
```

- Источник правды - база бота. Клиенты бота пишутся в `config.json` (с полем `email` = имя клиента) и одновременно добавляются в работающий Xray через API.
- **Общий клиент из скрипта autoXRAY становится клиентом `main`.** При установке (`patch`) бот берёт его под управление с тем же UUID, поэтому ссылки со страницы подписки моста продолжают работать. Для `main` доступны QR и ссылки, статус, история и трафик, но удалить его нельзя. Если скрипт моста запустить повторно, он создаст новый UUID: бот предложит восстановить конфиг и перенесёт `main` на новый UUID.
- Остальных клиентов без `email` бот не трогает.
- UUID генерируется с третьей группой `0000`, а в ссылку подставляется номер маршрута (`0001`). Так работает `vlessRoute` в мосту autoXRAY: по этой группе Xray выбирает, в какой EU-сервер отправить трафик.
- Шаблоны ссылок бот берёт со страницы подписки моста (`/var/www/<домен>/*.html`), подставляя UUID и имя клиента. Если страница не найдена, собирает ссылки из конфига Xray.
- Онлайн определяется по встроенной статистике Xray (`statsUserOnline`): у клиента есть активные соединения или он был активен последние 2 минуты. Access log Xray не включается.
- Счётчики трафика Xray сбрасываются при перезапуске, поэтому бот раз в минуту забирает их с обнулением и накапливает у себя.

## Требования

- RU сервер с установленным мостом autoXRAY (`bridgeTLSxhttp.sh`), Debian 12/13 или Ubuntu.
- Xray v26.11.9 или новее (ставится скриптом autoXRAY).
- Токен бота от [@BotFather](https://t.me/BotFather) и твой Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot)).

## Установка

```bash
git clone https://github.com/Rewertkin/autoXRAY_bot_control.git
cd autoXRAY_bot_control
sudo bash install.sh
```

Скрипт:
1. ставит Python-зависимости в `/opt/xraybot/venv`;
2. спросит токен бота, твой Telegram ID и домен моста и создаст `/opt/xraybot/.env`;
3. включит в конфиге Xray API, статистику и онлайн-трекинг (резервная копия: `config.json.bak`) и перезапустит Xray;
4. установит и запустит службу `xraybot`.

После этого напиши боту `/start`.

## Команды

| Кнопка / команда | Что делает |
|---|---|
| ➕ Новый клиент, `/new` | Мастер создания: имя -> тип -> срок -> подключения -> лимит |
| 👥 Клиенты, `/clients` | Список с онлайн-статусом, по нажатию карточка клиента |
| 📊 Трафик, `/traffic` | Сводка по всем клиентам |
| 🩺 Диагностика, `/diag` | Проверка сервера |
| 🌉 Проверить мост, `/bridge` | Зарубежный сервер из конфига моста: DNS, TLS, сайт-заглушка, цепочка RU -> EU |

В карточке клиента: QR и ссылки, история подключений, продление (для гостей), изменение лимита, удаление.

## Обслуживание

```bash
journalctl -u xraybot -f                                   # логи бота
sudo XRAYBOT_ENV=/opt/xraybot/.env /opt/xraybot/venv/bin/python -m xraybot check   # проверка настроек
```

Обновление бота:
```bash
cd autoXRAY_bot_control && git pull && sudo bash install.sh
```
`.env` и база при обновлении сохраняются.

Если повторно запустил скрипт моста autoXRAY (он перезаписывает `config.json`): нажми «🛠 Восстановить конфиг» в уведомлении бота или выполни
```bash
cd /opt/xraybot && sudo XRAYBOT_ENV=/opt/xraybot/.env venv/bin/python -m xraybot patch
```
Учти, что скрипт генерирует новый путь XHTTP, поэтому ссылки клиентов тоже изменятся: перешли им новые из карточки.

Удаление:
```bash
sudo systemctl disable --now xraybot
sudo rm -rf /opt/xraybot /var/lib/xraybot /etc/systemd/system/xraybot.service
```

## Безопасность

- Бот отвечает только Telegram ID из `ADMIN_IDS`, остальных игнорирует.
- Токен и настройки лежат в `/opt/xraybot/.env` с правами `600`. **Не коммить `.env`** (он в `.gitignore`).
- Служба работает от root (нужно править конфиг Xray и перезапускать его), но с `ProtectSystem=strict`: на запись доступны только `/usr/local/etc/xray` и `/var/lib/xraybot`.
- Связь с Telegram идёт через EU-сервер: `patch` создаёт для бота отдельный SOCKS-вход `127.0.0.1:10444`, направленный прямо в первый EU-outbound моста (`proxy-0`). Общий SOCKS моста бот не использует: он идёт через балансировщик autoXRAY, который при медленном пинге (больше 1 с) временно отправляет трафик в `block`.
- Геосервисы бот вызывает напрямую с RU сервера: через мост они заблокированы правилами autoXRAY.
